# 测试大纲

## 1. 测试目的

本文档用于说明 Minisys FmcPGA Minecraft TFT 体素渲染系统的测试范围、测试环境、单元测试用例、集成测试用例、自动化属性和人工测试步骤。测试目标是确认系统已经完成的显示、渲染、控制、音频、存储资源、构建脚本、下载脚本和 Flash 启动功能满足用户需求规格说明书中的要求。

## 2. 测试范围

### 2.1 纳入测试范围

1. TFT 时钟、时序和显示输出链路。
2. 320x240 RGB444 帧缓冲到 800x480 RGB323 TFT 的映射与颜色转换。
3. FmcPGA VHDL 渲染核心与 Verilog Minisys 顶层的混合语言集成。
4. 玩家移动、视角旋转、方块选择、放置和挖掘控制。
5. 准星目标反馈和右下角手持方块 HUD。
6. 蜂鸣器背景音乐、交互音效和背景音乐静音。
7. 源码级 IP 替代模块，包括 PLL、RAM、ROM 和 divider。
8. 地图、纹理和纹理索引资源初始化。
9. Vivado 工程创建、综合、实现、bitstream 生成和时序报告。
10. JTAG 临时下载、SPI Flash 持久化烧录、Flash 校验和上电启动。
11. PowerShell 静态检查脚本和 Vivado Tcl 自动化脚本。

### 2.2 不纳入当前测试范围

1. 全 VHDL 到 Verilog/SystemVerilog 的完整转换验证。
2. PS2 手柄接口恢复验证。
3. DDR3、外部 SRAM、文件系统、网络服务或软件后端测试。
4. 不同 FPGA 开发板或不同 TFT 屏幕型号的兼容性测试。

## 9. 人工测试详细步骤

### IT-MAN-01 开发板连接检查

前置条件：

1. Minisys 开发板、TFT 屏、JTAG 下载线和电源准备完毕。
2. 主机安装 Vivado 2018.3，并可识别 JTAG 设备。
3. 工程已生成 bitstream。

测试步骤：

1. 关闭 Minisys 开发板电源。
2. 检查 TFT 屏接口方向和连接是否牢固。
3. 检查 JTAG 下载线是否连接到开发板和主机。
4. 检查蜂鸣器相关连接或板载蜂鸣器是否可用。
5. 打开开发板电源。
6. 在 Vivado Hardware Manager 或 Tcl Console 中执行硬件连接命令。
7. 确认 Vivado 能识别 FPGA 设备。

通过标准：

1. Vivado 可以打开 hardware target。
2. `get_hw_devices` 至少返回一个 FPGA 设备。
3. 开发板电源、TFT 背光和 JTAG 连接状态正常。

### IT-MAN-02 smoke test TFT 显示

前置条件：

1. 已创建并综合 smoke test 工程。
2. smoke test bitstream 已生成或可在 Vivado 中生成。

测试步骤：

1. 在 Vivado 中打开 smoke test 工程或执行 `scripts/create_fmcpga_tft_smoke_project.tcl`。
2. 生成 smoke test bitstream。
3. 将 smoke test bitstream 下载到 FPGA。
4. 观察 TFT 屏幕是否有稳定图案输出。
5. 拨动部分拨码开关或按下按键，观察测试图案或 LED 是否有对应变化。
6. 按 S6 复位，观察显示是否能恢复稳定。

通过标准：

1. TFT 屏幕有稳定画面，无明显滚屏、闪烁、黑屏或错位。
2. 颜色输出明显可辨。
3. 复位后显示恢复正常。

### IT-MAN-03 正式 3D 场景显示

前置条件：

1. 已执行正式工程构建并生成 `minisys_fmcpga_tft_top.bit`。
2. 已通过 JTAG 下载或从 Flash 启动正式系统。

测试步骤：

1. 给开发板上电。
2. 下载正式 bitstream，或确认开发板已经从 Flash 启动。
3. 观察 TFT 屏幕。
4. 检查画面是否为 Minecraft 风格体素场景。
5. 检查画面是否水平居中，左右是否存在约 80 像素黑边。
6. 检查画面是否占据约 640x480 区域。
7. 检查颜色是否正常，不应整体偏色、反相或严重花屏。
8. 等待数秒，确认画面持续稳定。

通过标准：

1. 3D 体素场景可见。
2. 画面居中放大，左右黑边正确。
3. 同步稳定，无持续闪烁、滚动或撕裂到无法观察。

### IT-MAN-04 复位功能

前置条件：正式系统正在显示 3D 场景。

测试步骤：

1. 先通过移动或方块操作让场景状态发生变化。
2. 按下 S6。
3. 松开 S6。
4. 观察画面是否回到初始状态或重新开始渲染。
5. 再次执行一次移动操作，确认复位后系统仍可交互。

通过标准：

1. 按下 S6 后系统响应复位。
2. 松开后画面恢复稳定。
3. 复位后按键、显示和音频仍可正常工作。

### IT-MAN-05 移动模式控制

前置条件：

1. 正式系统运行。
2. 设置 `sw[6] = 0`，进入移动模式。

测试步骤：

1. 按下 S1，观察画面变化，记录是否表现为向右移动。
2. 松开 S1，确认移动停止。
3. 按下 S2，观察画面变化，记录是否表现为向左移动。
4. 松开 S2，确认移动停止。
5. 按下 S3，观察画面变化，记录是否表现为向前移动。
6. 松开 S3，确认移动停止。
7. 按下 S4，观察画面变化，记录是否表现为向后移动。
8. 松开 S4，确认移动停止。
9. 连续按不同方向，确认系统没有卡死或丢失显示。

通过标准：

1. S1/S2/S3/S4 分别对应右移、左移、前进、后退。
2. 松开按键后对应移动停止。
3. 多次操作后画面仍稳定。

### IT-MAN-06 视角模式控制

前置条件：

1. 正式系统运行。
2. 设置 `sw[6] = 1`，进入视角模式。

测试步骤：

1. 按下 S1，观察视角是否向右旋转。
2. 松开 S1。
3. 按下 S2，观察视角是否向左旋转。
4. 松开 S2。
5. 按下 S3，观察视角是否向上调整。
6. 松开 S3。
7. 按下 S4，观察视角是否向下调整。
8. 松开 S4。
9. 将 `sw[6]` 切回 0，确认 S1-S4 又恢复为移动操作。

通过标准：

1. `sw[6] = 1` 时按键改变视角而非平移。
2. `sw[6] = 0` 时按键恢复移动功能。
3. 切换模式不会导致系统卡死、黑屏或复位。

### IT-MAN-07 方块选择与 HUD

前置条件：正式系统运行，TFT 可见右下角 HUD。

测试步骤：

1. 设置 `sw[4:0] = 0`，观察右下角手持方块颜色。
2. 设置 `sw[4:0] = 1`，观察 HUD 是否发生变化。
3. 依次选择几个典型 ID，例如 2、3、5、10、15、23。
4. 每次拨码后等待画面刷新，记录 HUD 颜色或形态是否变化。
5. 设置超出推荐贴图范围但仍为 5 位的值，例如 24 到 31，观察 HUD 是否使用默认颜色或可接受显示。

通过标准：

1. `sw[4:0]` 改变后 HUD 有对应变化。
2. 推荐范围 0 到 23 内显示稳定。
3. 非推荐值不会导致显示链路异常。

### IT-MAN-08 放置方块

前置条件：

1. 正式系统运行。
2. 设置 `sw[6] = 0` 或 `sw[6] = 1` 均可。
3. 设置 `sw[5] = 0`，进入放置模式。
4. 使用 `sw[4:0]` 选择一个明显颜色的方块 ID。

测试步骤：

1. 通过移动或视角调整，将准星对准一个可放置位置附近的方块表面。
2. 确认准星目标反馈可见。
3. 短按 S5 一次。
4. 观察准星附近是否新增所选方块。
5. 修改 `sw[4:0]` 为另一个方块 ID。
6. 再次短按 S5。
7. 观察新放置方块是否与新选择的方块类型一致。
8. 连续执行 3 次，确认系统不黑屏、不复位。

通过标准：

1. `sw[5] = 0` 时 S5 执行放置。
2. 放置方块类型跟随 `sw[4:0]`。
3. 一次短按只触发一次放置。

### IT-MAN-09 挖掘方块

前置条件：

1. 正式系统运行。
2. 设置 `sw[5] = 1`，进入挖掘模式。

测试步骤：

1. 将准星对准一个可见方块。
2. 确认目标方块处于准星命中位置。
3. 短按 S5 一次。
4. 观察该方块是否消失或变为空气。
5. 移动到另一个方块，重复一次。
6. 将 `sw[5]` 切回 0，确认 S5 不再挖掘而是放置。

通过标准：

1. `sw[5] = 1` 时 S5 执行挖掘。
2. 被挖掘方块从场景中消失。
3. 切回放置模式后行为正确改变。

### IT-MAN-10 动作单次触发

前置条件：正式系统运行，准星对准可操作方块。

测试步骤：

1. 设置 `sw[5] = 0`，短按 S5，观察只放置一个方块。
2. 长按 S5 约 2 秒，观察是否没有连续快速放置大量方块。
3. 松开 S5。
4. 设置 `sw[5] = 1`，短按 S5，观察只挖掘一个目标。
5. 长按 S5 约 2 秒，观察是否没有连续挖穿多个方块。
6. 保持 `sw[5] = 1` 不动但不按 S5，观察是否不会自动挖掘。

通过标准：

1. S5 的一次按下只产生一次动作。
2. `sw[5]` 仅选择动作模式，本身不会触发连续动作。

### IT-MAN-11 准星目标反馈

前置条件：正式系统运行。

测试步骤：

1. 观察屏幕中心是否存在准星。
2. 移动或旋转视角，使准星对准实体方块。
3. 观察被选中方块或命中面是否出现高亮/颜色变化。
4. 将准星对准天空或无方块区域。
5. 观察目标反馈是否消失或不再指示实体方块。
6. 在有反馈时执行放置或挖掘，确认操作位置与准星指示一致。

通过标准：

1. 准星位置清晰。
2. 命中方块时有目标反馈。
3. 操作对象与准星反馈一致。

### IT-MAN-12 背景音乐

前置条件：

1. 正式系统运行。
2. 蜂鸣器可用。
3. 设置 `sw[7] = 0`。

测试步骤：

1. 上电或下载后等待 3 到 5 秒。
2. 靠近蜂鸣器听是否有周期性背景旋律。
3. 观察系统显示是否仍然稳定。
4. 等待一个较长节拍周期，确认音乐有音符变化而非固定单音。

通过标准：

1. 蜂鸣器有背景音乐输出。
2. 音乐不会影响显示和按键交互。

### IT-MAN-13 交互音效

前置条件：正式系统运行，蜂鸣器可用。

测试步骤：

1. 设置 `sw[7] = 0`，保持背景音乐开启。
2. 设置 `sw[5] = 0`，短按 S5，听是否有放置音效。
3. 设置 `sw[5] = 1`，短按 S5，听是否有挖掘音效。
4. 改变 `sw[4:0]` 低位后重复放置操作，听音效是否有变化。
5. 确认音效播放时背景音乐被短暂覆盖或音效更明显。

通过标准：

1. S5 能触发短音效。
2. 放置和挖掘音效可区分。
3. 音效优先级高于背景音乐。

### IT-MAN-14 背景音乐静音

前置条件：正式系统运行，蜂鸣器可用。

测试步骤：

1. 设置 `sw[7] = 0`，确认背景音乐正在播放。
2. 设置 `sw[7] = 1`。
3. 等待 3 到 5 秒，确认背景音乐停止。
4. 保持 `sw[7] = 1`，短按 S5。
5. 听是否仍能播放交互音效。
6. 将 `sw[7]` 切回 0，确认背景音乐恢复。

通过标准：

1. `sw[7] = 1` 后背景音乐静音。
2. 静音背景音乐时，S5 交互音效仍可播放。
3. `sw[7] = 0` 后背景音乐恢复。

### IT-MAN-15 LED 调试显示

前置条件：正式系统运行。

测试步骤：

1. 观察红色 LED 是否显示 FPS 高位相关状态。
2. 观察绿色 LED 是否显示 FPS 个位和当前物品相关状态。
3. 拨动 `sw[7]`，观察黄色 LED 最高位是否变化。
4. 拨动 `sw[6]`，观察黄色 LED 视角模式位是否变化。
5. 拨动 `sw[5]`，观察黄色 LED 动作模式位是否变化。
6. 按下 S5，观察黄色 LED 动作按键位是否变化。
7. 改变 `sw[3:0]`，观察黄色 LED 低位是否变化。

通过标准：

1. LED 随对应状态变化。
2. LED 变化不会影响 TFT 显示和控制功能。

### IT-MAN-16 SPI Flash 上电启动

前置条件：

1. 已成功运行 `scripts/program_fmcpga_tft_flash.tcl`。
2. 已成功运行或准备运行 `scripts/verify_fmcpga_tft_flash.tcl`。
3. 知道 Minisys 开发板从 SPI Flash 启动所需跳线设置。

测试步骤：

1. 在 Vivado Tcl Console 中执行 Flash 校验脚本。
2. 确认脚本报告 Flash 内容与 MCS 文件一致。
3. 关闭开发板电源。
4. 按 Minisys 手册将启动跳线设置为从 SPI Flash 启动。
5. 不执行 JTAG 下载命令。
6. 打开开发板电源。
7. 等待 FPGA 配置完成。
8. 观察 TFT 是否自动显示正式系统画面。
9. 测试 S1-S5、`sw[5]`、`sw[6]` 和蜂鸣器是否仍工作。
10. 如果 TFT 无画面，在 Vivado 中执行 `scripts/check_fmcpga_tft_boot_status.tcl`，记录 DONE、CONFIG、BOOT、STATUS 相关属性。

通过标准：

1. 不执行 JTAG 下载时，上电后系统自动启动。
2. TFT 显示正式 3D 场景。
3. 控制和音频功能与 JTAG 下载方式一致。

## 10. 回归测试建议

每次修改 RTL、约束、脚本或资源文件后，至少执行以下回归集合：

1. 运行四个 PowerShell 静态检查脚本。
2. 重新创建正式 Vivado 工程。
3. 运行综合、实现和 bitstream 生成。
4. 检查实现后时序报告。
5. JTAG 下载并完成显示、移动、视角、放置、挖掘、HUD 和音频人工冒烟测试。

如果修改涉及 Flash 脚本或启动方式，还应额外执行：

1. SPI Flash 烧录。
2. SPI Flash verify。
3. 断电重启从 Flash 启动测试。

如果修改涉及单个模块逻辑，建议先补充对应单元 testbench，再执行系统级回归。

## 11. 测试通过准则

系统测试整体通过需要满足：

1. 所有已自动化静态检查通过。
2. 正式 Vivado 工程可以重新创建、综合、实现并生成 bitstream。
3. 实现后时序报告无关键违例。
4. TFT 能稳定显示居中放大的 3D 场景。
5. 移动、视角、放置、挖掘、方块选择、HUD、背景音乐、交互音效和静音功能均通过人工验证。
6. JTAG 临时下载可用。
7. 若要求持久启动，则 SPI Flash 烧录、校验和断电上电启动均通过。
