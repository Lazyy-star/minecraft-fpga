# 用户需求规格说明书

## 1. 引言

### 1.1 项目名称

Minisys FmcPGA Minecraft TFT 体素渲染系统。

### 1.2 编写目的

本文档用于整理当前工程已经完成的用户需求、功能需求、运行环境、外部接口、验收标准和实现追踪关系，作为后续课程设计报告、答辩说明和系统测试说明的基础材料。

### 1.3 项目背景

本项目面向 Minisys FPGA 开发板，将原 FmcPGA Minecraft-like 体素渲染器移植到 Minisys 硬件平台，并通过板载外接 800x480 TFT 屏显示 3D 场景。工程采用保守的阶段式迁移方案：保留原 FmcPGA 的 VHDL 渲染核心，在外围增加 Verilog 板级顶层、TFT 显示适配、控制映射、蜂鸣器音频、源码级 IP 替代和 Vivado 自动化脚本，从而先完成可综合、可实现、可下载运行的混合语言硬件系统。

### 1.4 编写依据

本文档依据当前仓库中的 RTL 源码、约束文件、构建脚本、检查脚本、构建报告和已有设计记录整理，主要覆盖以下路径：

- `rtl/top/minisys_fmcpga_tft_top.v`
- `rtl/top/fmcpga_frame_test_top.v`
- `rtl/vhdl/fmcpga_core_flat.vhd`
- `rtl/tft/`

- `vendor/FmcPGA/`
- `mem/`
- `constraints/minisys_fmcpga_tft.xdc`
- `scripts/`
- `docs/build-notes/`
- `reports/`

## 2. 总体描述

### 2.1 系统目标

系统应在 Minisys FPGA 开发板上运行一个 Minecraft 风格的体素场景渲染系统，用户通过按键和拨码开关控制移动、视角旋转、放置方块、挖掘方块和选择方块类型，系统通过 TFT 屏实时显示渲染画面，并通过蜂鸣器输出背景音乐和操作音效。

### 2.2 用户角色

| 需求编号 | 用户角色 | 主要需求 |
| --- | --- | --- |
| UR-01 | 玩家/演示者 | 上电或下载后直接看到 3D 场景，通过按键移动、旋转视角、放置和挖掘方块，获得视觉与声音反馈。 |
| UR-02 | 开发者 | 能够复现 Vivado 工程、检查源码完整性、综合实现、生成 bitstream、下载到 FPGA 或写入 SPI Flash。 |
| UR-03 | 测试者 | 能够使用 smoke test、静态检查脚本、时序报告和硬件下载脚本验证显示链路、控制映射和构建结果。 |
| UR-04 | 报告撰写者 | 能够清晰说明系统架构、模块分工、已完成功能、运行环境、接口定义和验收依据。 |

### 2.3 运行环境

| 需求编号 | 类型 | 规格 |
| --- | --- | --- |
| ER-01 | FPGA 开发板 | Minisys |
| ER-02 | FPGA 器件 | `XC7A100T-FGG484-1` / `xc7a100tfgg484-1` |
| ER-03 | 开发工具 | Vivado 2018.3 |
| ER-04 | 主时钟 | `clk_100m`，100 MHz |
| ER-05 | 显示设备 | 800x480 TFT，RGB323 输出 |
| ER-06 | 渲染帧缓冲 | 320x240，RGB444 |
| ER-07 | 音频输出 | 蜂鸣器输出端口 `BUZZER_O` |
| ER-08 | 硬件描述语言 | Verilog + VHDL 2008 |
| ER-09 | 资源初始化 | COE 转 MEM 后由 `$readmemh` 初始化 RAM/ROM |

### 2.4 设计边界

| 需求编号 | 设计边界需求 |
| --- | --- |
| BR-01 | 已完成系统聚焦于 FPGA 端硬件渲染和板级交互，不依赖软件后端、数据库、网络服务或操作系统。 |
| BR-02 | 当前阶段未要求完成全 VHDL 到 Verilog 的彻底重写，原 FmcPGA 渲染核心仍以 VHDL 方式保留，并通过扁平化 wrapper 接入 Verilog 顶层。 |

## 4. 已完成功能需求

### FR-01 FPGA 体素场景渲染

系统已经接入原 FmcPGA 体素渲染核心，能够基于地图 RAM、纹理 ROM 和纹理索引 ROM 生成 320x240 RGB444 渲染帧缓冲。渲染链路保留了原工程中的视口扫描、射线/管线处理、颜色累积、天空/方块判断、目标方块选中和双缓冲显示结构。

实现依据：

- `vendor/FmcPGA/src/hdl/pipeline/`
- `vendor/FmcPGA/src/hdl/compute/`
- `vendor/FmcPGA/src/hdl/control/`
- `rtl/vhdl/fmcpga_core_flat.vhd`

### FR-02 Minisys 板级顶层

系统已经提供正式板级顶层 `minisys_fmcpga_tft_top`，负责连接 Minisys 时钟、按键、拨码开关、LED、TFT 和蜂鸣器接口，并实例化显示时序、FmcPGA 核心、HUD 叠加、颜色转换和音频模块。

实现依据：

- `rtl/top/minisys_fmcpga_tft_top.v`
- `constraints/minisys_fmcpga_tft.xdc`

### FR-03 混合语言集成

系统已经实现 VHDL 渲染核心与 Verilog 顶层之间的集成边界。`fmcpga_core_flat` 将原工程不易从 Verilog 直接连接的 VHDL record、复杂顶层端口和原 VGA/手柄接口改造为普通 `std_logic` 和 `std_logic_vector` 扁平端口，便于 Verilog 顶层例化。

实现依据：

- `rtl/vhdl/fmcpga_core_flat.vhd`
- `scripts/create_fmcpga_tft_project.tcl`

### FR-04 TFT 显示时钟与时序

系统已经提供 TFT 像素时钟和 800x480 显示时序生成模块，输出 `HSYNC`、`VSYNC`、`DE`、像素坐标和像素时钟，并在正式顶层中对同步信号与有效信号进行寄存，以匹配显示数据延迟。

实现依据：

- `rtl/tft/tft_clock_gen.v`
- `rtl/tft/tft_timing.v`
- `rtl/top/minisys_fmcpga_tft_top.v`
- `scripts/check_display_pipeline.ps1`

### FR-05 320x240 到 800x480 显示适配

系统已经实现从 FmcPGA 320x240 帧缓冲到 800x480 TFT 可视区域的地址映射。画面按 2 倍放大为 640x480，并水平居中显示，左右各保留 80 像素黑边。当前映射还对源图像 Y 坐标进行翻转，以匹配最终屏幕方向。

实现依据：

- `rtl/adapter/fmcpga_tft_read_mapper.v`
- `scripts/check_requested_adjustments.ps1`

### FR-06 RGB444 到 RGB323 颜色转换

系统已经完成 FmcPGA RGB444 像素到 TFT RGB323 输出格式的转换。颜色适配采用高位截断方式，适配 Minisys TFT 的 8 位 RGB 输出接口。

实现依据：

- `rtl/adapter/fmcpga_rgb444_to_rgb323.v`

### FR-07 显示链路 smoke test

系统已经提供 Verilog-only 的显示链路测试顶层 `fmcpga_frame_test_top`，可在不接入完整 VHDL 渲染核心的情况下验证 TFT 时钟、时序、地址映射、颜色转换、按键/开关输入和基本输出链路。

实现依据：

- `rtl/top/fmcpga_frame_test_top.v`
- `scripts/create_fmcpga_tft_smoke_project.tcl`

### FR-08 玩家移动控制

系统已经将 Minisys 按键映射为玩家移动控制。在 `sw[6] = 0` 时，S1/S2/S3/S4 分别控制右移、左移、前进和后退。按键信号在 VHDL 核心内部经过去抖处理后参与玩家状态更新。

实现依据：

- `rtl/top/minisys_fmcpga_tft_top.v`
- `rtl/vhdl/fmcpga_core_flat.vhd`
- `scripts/check_control_mapping.ps1`

### FR-09 视角旋转控制

系统已经实现独立的视角控制模式。在 `sw[6] = 1` 时，S1/S2 控制左右转向，S3/S4 控制上下视角，原移动偏移被关闭，避免移动和转向同时混杂。

实现依据：

- `rtl/vhdl/fmcpga_core_flat.vhd`
- `scripts/check_control_mapping.ps1`

### FR-10 方块选择

系统已经通过 `sw[4:0]` 实现方块 ID 选择。所选 ID 直接参与放置操作，并用于右下角手持方块 HUD 的颜色显示。推荐使用 0 到 23 范围内的 ID，以匹配当前纹理映射资源。

实现依据：

- `rtl/top/minisys_fmcpga_tft_top.v`
- `rtl/vhdl/fmcpga_core_flat.vhd`
- `rtl/adapter/fmcpga_hand_overlay.v`

### FR-11 放置方块功能

系统已经实现按 S5 执行一次放置操作。当 `sw[5] = 0` 时，S5 触发一次动作脉冲，系统在准星目标相邻位置写入 `sw[4:0]` 选择的方块 ID。

实现依据：

- `rtl/vhdl/fmcpga_core_flat.vhd`
- `vendor/FmcPGA/src/hdl/control/map_modifier.vhd`

### FR-12 挖掘方块功能

系统已经实现按 S5 执行一次挖掘操作。当 `sw[5] = 1` 时，S5 触发一次动作脉冲，系统将准星选中的方块写为 0，从而实现挖掘/清除方块。挖掘不再因为拨码开关保持高电平而连续执行。

实现依据：

- `rtl/vhdl/fmcpga_core_flat.vhd`
- `scripts/check_control_mapping.ps1`

### FR-13 动作单次触发

系统已经将 S5 动作按键处理为单次脉冲。动作信号经过按键去抖、跨时钟同步和上升沿检测后，生成 `action_pulse_ppl`，保证一次按下只触发一次方块修改。

实现依据：

- `rtl/vhdl/fmcpga_core_flat.vhd`

### FR-14 准星与目标反馈

系统保留并接入原 FmcPGA 的准星和目标方块选择逻辑。画面中心区域显示反色准星，渲染管线识别准星命中的方块与表面，选中方块会以高亮方式反馈，便于用户判断放置或挖掘对象。

实现依据：

- `rtl/vhdl/fmcpga_core_flat.vhd`
- `vendor/FmcPGA/src/hdl/control/crosshair_object_register.vhd`
- `vendor/FmcPGA/src/hdl/pipeline/pipeline_process.vhd`

### FR-15 右下角手持方块 HUD

系统已经实现屏幕右下角手持方块 HUD。HUD 根据 `sw[4:0]` 当前选择的方块 ID 显示不同颜色的简化立体方块，并与主渲染画面叠加输出，帮助用户确认当前将要放置的方块。

实现依据：

- `rtl/adapter/fmcpga_hand_overlay.v`
- `rtl/top/minisys_fmcpga_tft_top.v`

### FR-16 蜂鸣器背景音乐

系统已经实现蜂鸣器背景音乐。音频模块使用 100 MHz 主时钟产生方波音调，并按固定节拍播放原创慢速旋律，为演示提供持续音频反馈。

实现依据：

- `rtl/audio/buzzer_audio.v`
- `rtl/top/minisys_fmcpga_tft_top.v`

### FR-17 方块操作音效

系统已经实现方块操作音效。S5 触发时会播放短音效；放置模式根据所选方块低位产生不同音高组合，挖掘模式播放另一组下行动效。交互音效优先级高于背景音乐。

实现依据：

- `rtl/audio/buzzer_audio.v`

### FR-18 背景音乐静音

系统已经通过 `sw[7]` 实现背景音乐静音。`sw[7] = 1` 时关闭背景音乐，但 S5 操作音效仍会播放，使用户仍能获得操作反馈。

实现依据：

- `rtl/top/minisys_fmcpga_tft_top.v`
- `rtl/audio/buzzer_audio.v`

### FR-19 LED 调试显示

系统已经实现 LED 调试输出。红色 LED 显示 FPS 的百位和十位，绿色 LED 显示 FPS 个位和当前物品个位，黄色 LED 显示音乐静音、视角模式、动作模式、动作按键和部分方块选择状态，便于调试和演示。

实现依据：

- `rtl/top/minisys_fmcpga_tft_top.v`

### FR-20 源码级 IP 替代

系统已经用源码级 Verilog 模块替代原 Vivado IP，模块名保持与原 FmcPGA IP 实例一致。替代对象包括 PLL、显示 RAM、地图 RAM、纹理 ROM、方块纹理索引 ROM 和除法器，降低对 GUI 生成 IP 的依赖，提高工程可复现性。

## 5. 非功能需求

### NFR-01 可综合与可实现

工程应能在 Vivado 2018.3 下完成综合、实现和 bitstream 生成。当前工程已经生成实现报告和 bitstream，routed 时序报告中关键时序检查无违例。

### NFR-02 可复现性

工程不应依赖已提交以外的 Vivado GUI 状态来理解主要设计。正式工程、smoke test 工程、构建、下载、Flash 烧录、Flash 校验和静态检查均提供脚本入口。

### NFR-03 模块化与可维护性

系统应保持板级顶层、TFT 时序、显示适配、音频、IP 替代、VHDL 核心 wrapper 和原 FmcPGA 核心之间的清晰边界，便于后续替换模块或逐步进行 Verilog 转换。

### NFR-04 交互确定性

用户按键操作应具有可预测行为。S1-S4 在移动模式和视角模式下功能明确；S5 通过去抖和脉冲化保证一次按下只执行一次方块修改；挖掘/放置模式由 `sw[5]` 明确区分。

### NFR-05 显示稳定性

TFT 输出应提供稳定的像素时钟、同步信号、数据使能和颜色输出。系统对显示有效信号、同步信号和源像素有效信号进行了寄存，以匹配读 RAM 和颜色输出延迟。

### NFR-06 资源自包含

运行时不依赖外部文件系统、网络、数据库或软件服务。地图、纹理和索引资源在 FPGA 片上 RAM/ROM 中完成初始化和访问。

### NFR-07 硬件平台约束

系统应匹配 Minisys 的引脚、时钟和 TFT 接口约束，目标器件固定为 `xc7a100tfgg484-1`。迁移到其他开发板需要重新适配 XDC、时钟和显示接口。

## 9. 当前限制与后续扩展

1. 当前阶段保留原 FmcPGA VHDL 核心，尚未完成全 Verilog/SystemVerilog 转换。
2. 当前控制方案使用 Minisys 按键和拨码开关，未恢复原工程 PS2 手柄接口。
3. 当前存储使用片上 RAM/ROM，不包含 DDR3、外部 SRAM 或文件系统。
4. 当前方块 ID 推荐范围为 0 到 23，高于该范围的 5 位值可能缺少有效纹理映射。
5. 当前报告中的硬件功能验收需要结合实物显示、按键、蜂鸣器和 Flash 启动现象最终确认。

## 10. 结论

截至本文档生成时，工程已经完成从原 FmcPGA 体素渲染核心到 Minisys TFT 平台的主要移植工作，具备 3D 场景渲染、TFT 显示适配、按键移动、视角旋转、方块选择、放置/挖掘、准星反馈、手持方块 HUD、蜂鸣器音频、LED 调试、工程自动生成、自动构建、bitstream 生成、JTAG 下载、SPI Flash 持久化烧录和静态一致性检查等功能。该系统已经具备课程设计演示和后续报告撰写所需的完整功能描述基础。
